## Preserve and improve

The original [design](FINAL_DESIGN.md) remains a sound foundation: native Panda
meshes, configuration-derived poses, crisp traces, a persistent transport,
deliberate space, and depth around a selected object. Study already has pinned
URLs and source-bound scene joins. Controller goals, observed finger pads,
collision geometry and selected-surface contours already exist. Do not rebuild
them as if they were missing.

The main weakness established by source review is fragmented explanation.
The lab opens a historical case; Study holds broader records; Engine exposes
a source inventory; About introduces the older scope. None provides a concise
route through the October native evaluator findings. A first visitor must
infer the system's purpose from controls intended for someone already inside
an experiment. Whether the present spacing, lighting and density also need
correction remains a fresh browser-review question.

Keep the current high-contrast dark text and single-document compact reading
flow. Previous releases froze startup through layout feedback and clipped
phone evidence. The rejected path-traced preview took roughly 17 seconds and
was visibly noisy. Those retained failures are reasons to measure alternatives
before changing the rendering foundation.

## Composition and navigation

Use **System** as an expanded introduction reachable from the existing identity
and About entry. It explains capture, valid execution, confirmation, retained
regression and unresolved results in one connected drawing. Selecting a
component reveals its implemented scope, one representative result and a route
to that evidence. Preserve the source inventory one level deeper.

Use the existing **Study** entry as the research index, extended to include
native software regressions and transfer results. Keep one index and one
investigation path. Do not add a second dashboard with duplicate navigation.
Existing pinned laboratory and Study URLs continue to open directly. An
unpinned public introduction can offer “Inspect an experiment” immediately;
it must not make a returning investigator replay an entrance sequence.

The investigation hierarchy is:

1. The changed mechanism and the question being tested.
2. The decisive witness, with reference and changed behavior distinguishable.
3. The scoped result, failed obligation or missing evidence.
4. Exact source, checks, costs and remaining limits.

On desktop, give the decisive drawing most of the workspace and a readable
explanation beside it. Keep source details out of the initial visual field.
On phones, show the question, drawing, result and one next action in document
order. Detailed fields expand in that same document; exit and return remain
reachable. Transient controls can float, while evidence text has a solid ground.

Every selection preserves its generation, case, run or software source variant,
sample when one exists, and return location. A software event is not assigned
a simulated robot timestamp. Back, reload, a copied link, and an unavailable
source must all have deliberate behavior.

## Graphics and motion

**Refine the real-time scene first.** Preserve actual meshes and recorded poses.
Review workspace and grasp framing, silhouette separation, contact shadows and
selection at the actual device pixel ratio. Room detail should support depth
without taking attention from fingers, object and evidence. Keep annotations
in a crisp DOM/SVG layer. Shadows and reflections are display treatments, not
measurements of force or contact.

For paired runs, qualify an aligned split view alongside the existing ghost
overlay. A shared camera is appropriate only for compatible coordinates and
models. Never align by equal row number alone, extend ended recordings, or
make interpolated poses selectable as measured samples.

For the native cases, use vector event diagrams and visible reference links.
Depth can distinguish live, retained and adjudicated layers, but quantitative
axes stay planar. There is no source for a photorealistic robot in those tests.
The episode plate demonstrates this distinction without introducing invented
telemetry or a generic decorative robot.

Evaluate **WebGPURenderer/TSL** in a separate renderer comparison only after
the current scene is measured. Three.js documents WebGL2 fallback and a new
post-processing stack, but also migration limits and possible performance
advantages for the existing renderer. This is a candidate technique, not an
automatic quality upgrade. [Three.js renderer guidance](https://threejs.org/manual/pages/webgpurenderer.html).

Consider restrained ambient occlusion and improved shadow sampling only when
they improve finger/object separation in both grounds without obscuring exact
marks. Avoid depth of field, bloom across evidence, film grain and accumulation
that delays input. NVIDIA likewise separates interactive and path-traced
workloads; its RTX capabilities do not transfer to this browser renderer.
[Isaac Sim rendering modes](https://docs.isaacsim.omniverse.nvidia.com/latest/reference_material/rendering_modes.html).

Keep one restrained translucent control layer. Apple's material guidance places
glass in navigation and controls rather than throughout content. This matches
the existing floating transport; it does not require copying native effects.
[Apple materials](https://developer.apple.com/design/human-interface-guidelines/materials).

Use short selection transitions after the new reading is admitted. Element-scoped
view transitions are an optional enhancement for an explanation surface, with
feature detection and an immediate reduced-motion path. Do not snapshot or
recreate the robot canvas during every navigation. The current 140 ms content
arrival is already implemented and should be compared before replacement.
[Chrome scoped transitions](https://developer.chrome.com/docs/css-ui/view-transitions/element-scoped-view-transitions).

Foxglove already supports time-aware spatial visualization and comparison;
Rerun uses columnar chunks for efficient ingestion. Nisayon's design opportunity
is the path from a changed mechanism to a qualified conclusion, not the mere
presence of a 3D robot or synchronized plots. Profile transfer, hashing, decoding,
allocation and first draw before introducing a binary pose format.
[Foxglove 3D](https://docs.foxglove.dev/docs/visualization/panels/3d),
[comparison](https://docs.foxglove.dev/docs/visualization/comparison-mode),
[Rerun chunks](https://rerun.io/docs/concepts/logging-and-ingestion/chunks).

## Make updates reliable

Keep four dates distinct: experiment execution, evidence verification, UI release
and latest discovery check. “Catalog checked now” does not make September evidence
current. Show the evidence date near the result and explain stale publication in
ordinary language. The site must not claim knowledge of a local failure unless
a reviewed public status record actually carries it.

Retain the old Study and scene generations. Repair historical export admission
through a reviewed source revalidation that checks unchanged measurements and
decisions; never edit the stored dependency hashes merely to silence refusal.
The current dependency function binds all engine/evaluator modules and the
interpreter. Its drift needs deliberate reconciliation with the current source.

Introduce a small versioned research catalog for **explicitly admitted result
types**, starting with the native episode case. Bind each projected result to
the original committed files, source revision, byte hashes, schema and adapter.
Project only public fields. Validate denominator, scope and upstream attribution
as part of the adapter, rather than generating a new conclusion in the browser.
New scientific records can advance discovery after validation. New schemas,
instruments and runtime bundles require a qualified application release.

Automatic publication remains an atomic promotion of reviewed immutable data
through the existing frozen runtime. Keep selection pinned, expose a newer
publication explicitly, preserve old links, and leave the last verified version
usable after a failed update. No new cloud service or live robot connection is
needed for this slice.

1. **Complete browser reconnaissance.** Desktop in both grounds; phone portrait,
   landscape and enlarged text; lab, Study, Processor, Temporal, Decision and
   Inspector. Exercise selection, return, startup and failure paths. Capture
   real screenshots and timings before changing the composition. Browser
   discovery currently returns no available connection; reconnection is pending.
2. **Build one complete native investigation.** A verified projection of the
   episode case, the event diagram, before/after source variants, 41-check matrix,
   preserved invalid attempts, upstream credit, source and limitations. Connect
   it to Study and the System explanation. Do not force it through the Lift schema.
3. **Reconcile freshness and extend the evidence map.** Add A1/B2 and the linked
   processor case through their own admitted types. Requalify the historical
   export independently. Keep architecture status distinct from result status.
4. **Refine the measured lab.** Compare framing, paired views and lighting at the
   same retained moments and devices. Keep the old renderer available through
   the comparison; select the better measured implementation.
5. **Qualify and release.** Exact file readback, stale/corrupt-source behavior,
   keyboard and focus continuity, reduced motion, small-height layout, and
   browser/device results accompany the production candidate.

For controls and prose, test reflow at 320 CSS pixels and 400% desktop zoom.
The exception for two-dimensional graphics does not permit clipped explanations.
Keep 44 px touch targets where practical. Test actual Safari/PWA separately from
desktop emulation. [W3C reflow guidance](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html).

Use event-to-paint and frame measurements alongside the existing DOM-commit and
GPU timing instruments. Field INP targets at most 200 ms at the 75th percentile,
segmented by device; a short local trace does not establish that field result.
For a selected 60 Hz interaction profile, 16.7 ms is the frame budget, not a
claim about the 20 Hz recorded policy trajectory. Report cold/warm startup,
sample count, device, cache, network, long tasks and context-loss recovery.
[INP guidance](https://web.dev/articles/inp).

The comprehension check is concrete: without coaching, a reviewer should find
the changed source, decisive witness, scoped conclusion, remaining uncertainty
and exact evidence, then return to the same selection. Record task errors and
completion time before and after. A design plate, unit suite or renderer API
choice cannot establish that result.
