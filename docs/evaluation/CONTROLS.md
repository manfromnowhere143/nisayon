# Synthetic development controls

**`evidence_origin: synthetic_development` · evaluator behaviour only, not experiment results.**

Every scenario is generated by rule from one positive bundle by `python -m nisayon.evaluation fixtures`.
`python -m nisayon.evaluation controls` evaluates all of them and exits nonzero when any
observed decision or expected reason code differs from this table. The retained machine
record is [synthetic-controls.json](results/synthetic-controls.json); a test fails when it
drifts from the code. A rejection-only evaluator would fail the `accepted` rows, which
include a strict version 0.2 positive control.

| `capture_stamps_inconsistent` | invalid | `capture_stamps_inconsistent` | An observation's stamp disagrees with its components' acquisition times. |
| `capture_after_action` | invalid | `observation_after_action` | A consumed component was acquired after the action executed. |
| `policy_state_carried_in_candidate` | rejected | `reset_obligation_violated` | The candidate's reset carries recurrent state from an earlier episode. |

Reproduce one scenario and read its decision:

```sh
uv run --frozen python -m nisayon.evaluation fixtures --out /tmp/nisayon-fixtures \
  --scenario invalid_replay_old_future_observations
uv run --frozen python -m nisayon.evaluation evaluate \
  /tmp/nisayon-fixtures/invalid_replay_old_future_observations
```
