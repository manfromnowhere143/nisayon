# Selection rule for task-qualification-001

**21 September 2026 · evaluation lane · frozen at 06:14 UTC, before any inventory command.**
Machine form: [`selection-rule.v1.json`](selection-rule.v1.json).

The question is narrow: does this machine already hold one executable policy task on
which a working and a changed deployment can differ only in the bound normalizer
statistics, with an observable outcome, so that a keep/replace decision can be adjudicated
prospectively and confirmed? The population is what is present at the phase start; nothing
is acquired during screening, and this lane makes no network request.

A candidate qualifies only if all seven criteria hold: a held policy checkpoint with
revision, digest and a license permitting local execution; a held executable source
revision that imports on this machine without new dependency bodies; an inspectable
statistics path bound to held statistics bytes; an executable task with a measurable
outcome that runs here without paid compute, hardware or an unmet GPU need; a realizable
intervention that changes only the bound statistics; custody of every input from retained
bytes; and no authority beyond the existing one.

The budget is a read-only inventory of six roots, at most twelve candidates, sixty process
CPU seconds and zero network. Every screened candidate and its first failed criterion is
retained. If nothing qualifies, the deliverable is an evidence-acquisition result for the
best-scored candidate: exact assets, sizes, sources, licenses, compute needs and cap
conflicts. No incident is manufactured and no toy is substituted. The remedy class is
already exposed to both lanes; any GR00T/LIBERO study is labelled exposed.
