# Research basis for the next evidence boundary

Reviewed 24 October 2026. These are selected current primary sources, not an
exhaustive frontier ranking. Published results were reviewed, not reproduced.

| Source and review scope | Relevant finding and implication |
| --- | --- |
| [SEAR, arXiv:2610.18792v1](https://arxiv.org/html/2610.18792v1), 13 October; abstract, selected methods, evaluation and seal/transfer appendices | The paper separates inherited library benefit from extra attempts, and reports an inspected saved verifier that misclassified later outcomes. **Our inference:** retained procedures need explicit applicability conditions; successful storage does not establish reliable transfer. |
| [LADDER, arXiv:2610.18053v1](https://arxiv.org/html/2610.18053v1), 13 October; abstract, selected verification and measurement sections | Long-horizon progress and verification have measurement limits. **Our inference:** a software check and a physical task verdict must retain different scopes. |
| [RoboValue, arXiv:2610.26663v1](https://arxiv.org/abs/2610.26663), 19 October; abstract only | Its evaluation distinguishes task state, progress, failure/recovery and value consistency. This reinforces the need for explicit judgment dimensions; we did not audit its full method or reproduce its scores. |
| [NVIDIA: The Machines that Make the Machines](https://developer.nvidia.com/blog/the-machines-that-make-the-machines/), 7 October; system discussion and lessons in the article body | The deployment account chooses perception, control and learning around concrete manufacturing constraints. **Our inference:** qualify a consequential failure before expanding the engine's abstraction. |
| [Hugging Face LeRobot: EnvHub and Isaac Lab Arena](https://huggingface.co/docs/lerobot/envhub_isaaclab_arena), current documentation | Shared simulation environments and accelerated policy evaluation already have substantial tooling. Those capabilities alone would not differentiate Nisayon. |
| [Inspect Robots](https://arxiv.org/abs/2610.06306) and [Robo-COP](https://arxiv.org/abs/2610.09228), October; abstract/current project context and the preceding retained review | Agent/VLA evaluation and policy-adoption checks are occupied capabilities. This experiment does not establish superiority over either system. |
| [CPython audit hooks](https://docs.python.org/3.12/library/sys.html#sys.addaudithook) and [audit event definitions](https://docs.python.org/3.12/library/audit_events.html), current 3.12 documentation | Hooks expose bounded runtime events but are not a sandbox. Registration can be refused by an earlier hook. The implementation verifies registration and records `open` attempts without claiming complete I/O coverage. |

The resulting engineering question is narrow: can a reused software verdict
overlook changed normalization data because only code was declared? The retained
experiment answers that question and tests a bounded correction in Nisayon.
It does not establish a new robotics benchmark, automatic causal diagnosis or
an economic advantage. A live owner comparison with all setup and review effort,
followed by untouched reuse, remains the next value test. General dependency
graphs and adaptive experiment selection still require that evidence.
