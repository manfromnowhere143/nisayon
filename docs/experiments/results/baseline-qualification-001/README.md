# Conventional processor baseline qualification

The replacement conventional baseline computes its own decisions from retained input
contents. It qualifies a comparator implementation for a future study. It does not
repair the previous comparison or establish an advantage for Nisayon.

## Result

The prior arm imported Nisayon processor helpers and then wrote three fixed verdicts.
That source remains the before-record at `34bda84`. The corrected
`conventional-content-derived-v1` diagnostic has no Nisayon imports. It independently
parses the retained JSON, safetensors and upstream source, performs float32 numeric
checks, derives obligation states and seals its verdicts. Its final source identity is
`f69727a` (`53dc34d0…`).

The plan was frozen before execution. All discriminating controls passed:

- opaque names and order preserved content-derived outcomes;
- deleting the supported candidate's state standard deviation changed support to
  rejection;
- complete valid content under the formerly rejected `C0_as_is` name changed rejection
  to support;
- a legitimate visual `IDENTITY` path remained valid; and
- incomplete and order-dependent ambiguous paths were refused.

On the retained incident, the diagnostic rejects C0 exact lookup and C1 suffix matching.
It supports C2 only as a software correction. Separate reference assessment agrees on
all three candidates, with no false acceptance or refusal. Deployment applicability is
still unresolved and no robot task ran. The integrated before/after, sealed-artifact and
evaluation-control digests are in
[qualification-readback-002.json](qualification-readback-002.json).

The first sealed run remains evidence. Its separate assessment failed because the
producer used an unsupported provenance label on a visual `IDENTITY` row. The row uses
no statistics; commit `e66f478` narrowly bound it to the retained artifact, and the
second sealed run passed the same frozen controls and separate assessment. The failed
command is not relabelled as a scientific pass.

Evaluation then added a frozen label-only control, E6. At `e66f478`, changing only
caller-supplied provenance and selector declarations falsely promoted C2 deployment
binding to supported even though no evidence changed. That failure is retained. Commit
`f69727a` makes those annotations declarations only: this input contract cannot establish
statistics interpretation or target-deployment selection. The same E6 plan now returns
C2 software-supported and deployment-unresolved; reference v2 agrees on every candidate,
records no false binding acceptance and names the two unestablished declarations. This
qualifies the binding conclusion to return unresolved; it does not establish binding.

## Deployment binding

The two-link search is exhausted. The retained old model metadata names
`lerobot/svla_so101_pickplace`, but it does not pin a dataset revision, state coordinate
order/units, original statistic bytes or a deployment invocation. The current public
dataset revision has six-element state/action statistics, but it postdates the retained
model revision and all 24 mean/std elements differ from the C2 values. It therefore
cannot substitute for original training provenance or identify the deployment selector.

No prospective binding plan was opened. The exact evidence request is: original
`train_config.json` or equivalent invocation under custody; selected dataset and exact
revision; state feature order and units; normalization mode; statistics bytes and their
origin; and the target-deployment configuration/invocation linking that selection to
those statistics. [deployment-binding-001.json](deployment-binding-001.json) retains the
accesses, byte identities and stopping decision.
