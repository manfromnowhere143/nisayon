# An unchanged contract rejects an unsuitable current proposal

24 October 2026. A frozen executable CPU mixing contract bound to the exact base
and head of [Kornia PR #5958](https://github.com/kornia/kornia/pull/5958) without
an adapter or checker edit. Native Python and Nisayon made the same four scoped
decisions: reject both current revisions and the precision-damaging control;
accept the previously qualified correction. Neither current revision is a
qualified working deployment. This tests reuse of a known invariant on another
proposal; it does not discover a new failure mechanism or qualify the proposal's
new independent-generator feature.

The [executable example](../../../../examples/qualification/kornia_mix/README.md)
binds complete source snapshots, exact environment premises and explicit CPU
semantics. Both workflows receive the same checker and conditions. The core SDK
and dependency lock are unchanged. A benefit from the common package belongs to
both workflows; this is one domain contract, not a general contract compiler.

## Evidence and selection boundary

The package and [protocol](PROTOCOL.md) were [frozen](freeze.json) at
04:27:23 UTC, before new selection. The separate selector considered all 38 open
Kornia proposals, of which 30 were non-draft and created within the declared
30-day window. Creation time, then PR number, determined the order. Three earlier
proposals were inapplicable; #5958 was the first source-applicable proposal.
Selection took 259 seconds within the 1,800-second cap, without native execution.
[Selection, exact revisions and applicability](selection/selection.json);
[candidate ledger](selection/candidate-ledger.json).

The current base is `6bb63bac1b480d7351ebbc6fd554d5c06d5145ea`; the head is
`fe71400f53bce6e02772f52ff2a6f7d4973d6dd4`. Both were checked against the frozen
original `4f4c9d61ecdbc38511ce08e3018ad3a3c3a78d1f` full-precision oracle and
known-bad half-precision control. GitHub reported the proposal as unmergeable;
no merge or rebase was performed. Immutable archive URLs, hashes and license
identities are in [selected-sources.json](selected-sources.json).

The prior selector's discovery response already contained #5958's title and
body. The literal frozen exclusion rule concerned prior **solver** exposure,
registered interactions and earlier study variants; no such exposure was found
for #5958. An initially broader selector-only exclusion was corrected before any
native outcome. Under that more conservative interpretation, no eligible case
remains. Both interpretations and the initial screen are retained in the
[clarification](selection/exposure-clarification.json). This is context-separated
model selection, not independent human replication or proof of globally unseen
source. Fresh seeds do not make the known failure mechanism new.

The selected proposal changes the actual mixing calls and their dependencies,
while preserving the observed default/global-stream interface. Optional explicit
`torch.Generator` routing, accelerator execution, compilation, full-PR adoption
and robot-task acceptance remain outside this contract.

## Results

Both restricted workflows used the unchanged 58 exposed conditions. Their OS
order was sampled before execution: native, then Nisayon. Both current revisions
retain the CPU half-precision sampler failure; the precision control completes
all calls but violates the full-precision relation. All eight bindings and
eight executions completed without retry. Completion is separate from acceptance.

| Source | Exposed conditions satisfying the contract | Fresh conditions satisfying the prior oracle | Native decision | Nisayon decision |
|---|---:|---:|---|---|
| Current base | 28/58 | 16/32 | reject | reject |
| Current head | 28/58 | 16/32 | reject | reject |
| Exposed qualified correction | 58/58 | 32/32 | adopt | adopt |
| Exposed unconditional-float32 control | 42/58 | 24/32 | reject | reject |

[Original workflow results](selected-result.json) and
[observation summary](selected-observations-summary.json) retain the distinction
between runtime errors and semantic failures. No verdict was transferred from
the old source: each new binding executed its reference, negative control and
candidate. The whole 14,897-file runtime was hashed before reserved evaluation;
the two arms could not read each other's results or the reserved records.

The evaluator then executed 32 reserved conditions per candidate, preserving all
128 candidate outcomes and 32 auxiliary original-baseline observations. Both
frozen decision sets matched all four independently graded decisions, with zero
false acceptance among three unsuitable sources per workflow. The denominator
contains two related revisions and one exposed control; it is not a population
error-rate estimate. Base and head had identical fresh semantic observations:
this does not show that the new generator feature introduced a regression.

One unchanged replay of both original 58-input procedures reproduced all eight
decisions and all 24 reference/control/candidate role outputs, including raw
semantic observations, native call counts and source hashes. No execution or
replay process failed or required retry. Package, SDK, source file sets and the
recorded environment identities remained unchanged. The prior evaluator oracle
shares native Torch primitives and the observer; it is not an external human
replication and does not separately validate every checker obligation.
[Evaluation and limits](evaluation/EVALUATION.json),
[released fresh inputs](evaluation/fresh-inputs.json),
[replay review](evaluation/replay-review.json).

All four selected portable bundles reproduce these decisions with native source
and environment unreadable and native imports/process execution guarded.
[Portable review receipt](selected-portable-review.json). This is reassessment
of retained observations, not another native confirmation or proof of physical
truth. Deployment decisions remain `unresolved`.

## Qualification and failures before selection

Both modes made all five expected decisions on prior exposed variants, four
rejections and one scoped adoption, using the same 58 conditions. The controls
cover the original defect, premature scalar rounding, unconditional precision
reduction and a diagnostic that does not repair the defect.
[Qualification decisions and commands](qualification.json).

All 28 new boundary checks pass. A constructed import-shadow check initially
failed: an added `torch.py` could change import resolution while every recorded
file remained untouched. The final binding check rejects changes to the complete
file set. The [failed prefix](shadow-before.txt) and
[final unit receipt](unit-checks.xml) are retained. Two earlier package versions
and all three qualification attempts remain in the evidence and cost records.
The five exposed portable bundles also pass the restricted review.
[Original portable check](portable-review.json).

## Costs and implication

| Measured selected work, four candidates | Native Python | Nisayon |
|---|---:|---:|
| Binding, including reference preparation | 11.01 s | 11.45 s |
| Execution and immediate review | 21.66 s | 45.59 s |
| Binding plus workflow | 32.67 s | 57.04 s |

The measured Nisayon workflow costs more wall time here. Its export and
instrumentation do additional work; the table is not a complete-cost comparison
of identical deliverables. The native comparator shares all semantic knowledge
and reusable automation. There were no new model solver calls. The shared source
preparation took 5.58 seconds; the enclosing driver took 95.41 seconds, including
both arms and preparation. Nested clocks must not be added again.

Package preparation's retained calendar window was 576.16 seconds, including
three qualification attempts. Selection and confirmation preparation took
480.32 seconds through final verification, containing the 259-second selection
interval. These calendar clocks are not continuous active effort. Fresh
confirmation took 8.28 seconds and replay 93.15 seconds, including binding and
immediate review. The evaluator's full calendar window through final
verification was 422.52 seconds and contains those execution clocks. The
[cost ledger](costs.json) retains attempts, reviews, setup and publication-check
failures. Earlier research and original procedure development, provider charges,
coordinator/evaluator tokens, active human effort and later adoption/maintenance
are incompletely measured. Unknown is not zero. The twofold complete-cost target
remains unproven; one related proposal and dependent controls cannot establish a
population false-acceptance rate or customer savings.

The result supports retaining executable semantics with explicit applicability.
It supplies no reason to add a more complex selector or build a broad robotics
runtime. The next value test needs an owner decision with material setup or review
work and complete effort measurements through initial preparation and subsequent
use. Portable review is a candidate source of value, but avoided owner effort has
not been measured here.

## Research basis and reproduction

The [primary-source review](SOURCES.md) covers ContractSkill (March 2026), the
September Microsoft/Cornell study of contracts and subagent execution, and
NVIDIA's 21 October Isaac platform announcement. These informed the experiment;
their reported results were not reproduced and do not establish Nisayon's
competitive superiority.

From a source checkout with the frozen base environment installed:

```sh
uv run --frozen python docs/experiments/results/contract-reuse-2026-10-24/inspect_bundles.py
uv run --frozen pytest tests/qualification/test_kornia_mix_package.py
```

The first command verifies all nine portable assessments without Kornia or Torch.
For native execution, follow [the reproduction guide](REPRODUCE.md), the [package commands](../../../../examples/qualification/kornia_mix/README.md),
the exact source identities above and the [prior correction reconstruction](../untouched-reuse-2026-10-23/REPRODUCE.md).
The frozen package requires the recorded Python binary, macOS/arm64 environment
and distribution identities. Another platform requires new qualification; it
cannot inherit this result by installing similarly named dependencies.
