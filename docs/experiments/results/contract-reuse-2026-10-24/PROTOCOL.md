# Executable-contract reuse gate

Freeze this protocol and the qualified package before asking the existing
selector/evaluator to identify a new case. The extraction uses only the exposed
23 October Kornia sources and checks. No new incident has been selected during
artifact authoring. This gate precedes another expensive solver comparison.

## Question and comparison

Can the frozen CPU mixing contract bind and qualify another current integration
decision without editing its semantic checker, observer, adapter or runner?
Both native Python and Nisayon receive exactly the same package, native sources,
conditions and semantic information. This isolates the work each workflow adds.
Benefits of the common package belong to both workflows. Do not attribute them
to the SDK, or compare an automated treatment to a baseline denied the checker.

First qualify package behavior on all five previously exposed variants. Require
four rejections and one scoped adoption in both modes, plus rejection of changed
source, environment and input-domain premises. This is engineering qualification,
not an independent replication or new incident. Preserve failed prefixes.

## Selection after the freeze

Continue the previously authorized selector/evaluator role. Selection must finish
within 30 minutes of active search; retain inspected candidates and exclusion
reasons. Use public licensed sources and existing local records only. No external
messages, paid compute, model weights or hardware. Read-only upstream review is
permitted. Use an owned source snapshot, never alter a sibling session's checkout.

An eligible case is a currently open, non-draft Kornia change within 30 days of
selection, with exact base/head, that changes one of the three qualified entry
points or its native sampling/mixing dependencies and preserves the stated input
and output contract. Exclude PR 6277, its revisions, merges, rebases, equivalent
fixes and all earlier exposed study variants. A different URL is not a new
incident. Exclude proposals already inspected by either solver in the prior
exposure inventory or registered Nisayon interactions. Unrelated Kornia features
are inapplicable; imports alone do not make them eligible.

Sort eligible public proposals by creation timestamp, then PR number; choose the
first. The selector may inspect source to establish eligibility but must not run
this package or choose based on a successful result. Retain the query time,
search coverage, exact revisions, license and applicability rationale. Record
`no_eligible_case` if none qualify; do not broaden or tune the package after
inspection and call the result untouched reuse.

If a case is found, the evaluator freezes at least 32 fresh conditions within the
contract scope and meaningful known-bad controls before releasing the case. Keep
those records outside the execution context until workflows and decisions freeze.
Shared filesystem access is not isolation. A model-selected case is independent
of the solver context only; it is not an external human replication.

## Execution and stopping rules

Before allocating new solver calls, check that unchanged binding succeeds and
the case warrants a complete-cost comparison. If the new source, API, input
domain, environment or contract differs, record inapplicability. Do not silently
adapt, drop a condition, or change a threshold. A revised package would need new
qualification and another untouched selection.

On an eligible unchanged binding, run both workflows serially on the same host,
with OS-random order retained before execution. Keep all three roles and every
condition. The independent evaluator checks decisions, false acceptance, fresh
confirmation and one unchanged replay. An executed process is not acceptance.
Failure or unresolved output is retained, not replaced by an easier case.

## Costs and claim boundary

Retain the package-build and qualification costs, selection, dependency setup,
binding, all executions, failures/retries, confirmation, review and delivery.
Report preparation once as a common cost, not as a free resource. For repeated
use report accumulated cost including the original preparation; a steady-state
latency ratio alone is not a complete-cost ratio. The native comparator may use
the same automation and reusable knowledge. Do not equate unequal work or
different decision quality.

The target remains at least 2× lower complete cost at matched decision quality.
Provider charges, coordinator/evaluator tokens, active human effort and later
adoption/maintenance have missing measurements; unknowns never become zero.
Report observable components and what is missing. One current software case,
dependent controls and local replay do not establish population error rates,
customer savings, robot acceptance or a general competitive advantage.
