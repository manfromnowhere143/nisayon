# Native qualification, portable review and the next cost test

23 October 2026. Nisayon exposes a Python SDK and `nisayon-qualify` for a
bounded native software decision. An explicit owner project and Python
environment supply reference, failure-control and candidate calls. Plans bind
declared inputs, source and environment; attempts retain interrupted work.
Software qualification and deployment acceptance remain separate.

The [native guide](../../../NATIVE_QUALIFICATION.md) includes a runnable example.
[Portable review](../../../PORTABLE_REVIEW.md) exports the complete store and
recomputes its assessment without executing native code. These interfaces have
no hosted service, physical-control adapter or automatic deployment permission.

## The planner did not earn a cost advantage

The 22 October development experiment connected the existing finite decision
planner to the installed SDK on pinned XPolicyLab helpers. A competent fixed
baseline used the cheapest known decisive probe. Both arms had the same source
information and four available probes. Seven exposed scenarios ran three times
per arm; fresh software inputs checked every keep or replace proposal.

| Observation | Fixed probe | Planner |
| --- | ---: | ---: |
| Expected decisions matched | 21/21 | 21/21 |
| Confirmed software replacements | 6 | 6 |
| Keep / reject / unresolved | 3 / 3 / 9 | 3 / 3 / 9 |
| Observed false acceptances | 0 | 0 |
| Native assignment attempts | 279 | 279 |
| Measured workflow seconds | 196.574 | 193.320 |
| Confirmation seconds, included above | 150.257 | 147.372 |

Both arms selected the same diagnostic probe every time. The 1.017 ratio of
measured workflow times is far below two and is not a robust selection advantage
on this shared workstation. A prefix-only defect passed diagnosis and failed
fresh confirmation in all six arm/repetition combinations. Missing native-call
evidence and ineffective controls remained unresolved.

Confirmation consumed 76.4% of baseline time. Holding that measured sequential
confirmation implementation and schedule unchanged, making everything else
free caps speedup at 1.308. This is a conditional accounting calculation, not
a universal performance bound. Zero observed false acceptances in these
constructed cases is not a statistical reliability guarantee.

The first campaign failed because the new single-arm joint fixture used the
wrong field name. Its 127.737 seconds and original evidence remain retained.
The corrected campaign took 390.204 seconds across both arms and bookkeeping.
A missing locked test dependency and campaign-level cancellation defect were
also corrected and retained. Human effort, model/provider charges, compute
charges and allocation of shared development remain incomplete; the
[complete-cost assessment](target-assessment.json) is **unresolved**.

The [aggregate record](comparison.json) is copied unchanged from the qualified
campaign. It exposes every assignment and its scope. Its raw-store references
identify retained research records; those private stores and historical native
environments are not distributed in this snapshot. This is aggregate readback,
not independently reproduced raw evidence. The new portable example and source
controls are reproducible from the public checkout.

## What research changes about the next test

[EmbodiedRSI](https://arxiv.org/html/2610.10498v1) already combines hypotheses,
cost-aware experiment selection and memory. [NVIDIA ENPIRE](https://research.nvidia.com/labs/gear/enpire/)
already builds a physical improvement loop. These are reviewed primary sources,
not reproduced results or evidence of Nisayon's superiority.

[AgentCL v3, 26 September](https://arxiv.org/html/2606.02461v3) separates related
task streams, frozen-memory reuse and independent tasks; memory can also degrade
performance. Its framework supports declaring the reuse relationship before
looking at a second answer. NVIDIA's [11 July evaluation article](https://developer.nvidia.com/blog/how-to-evaluate-general-purpose-robot-policies-for-real-world-deployment/)
also makes the native baseline stronger: it includes graded outcomes, failure
events and environment sensitivity. A log archive alone is not the advantage.

The [owner comparison procedure](../../../OWNER_COMPARISON.md) therefore keeps
the twofold complete-cost target at matched decision quality, competent native
tools plus agent access, false-acceptance controls and fresh task confirmation.
The opportunity to test is avoidable setup, adaptation or review. Freeze the
procedure after one live decision, then test a separate untouched case, including
an invalid-transfer control. The current owner intake lacks the required records;
the live comparison and untouched reuse have not been executed.

The current release integration is a separate software qualification. Its
checks cannot replace that owner experiment. The original 172 focused installed
tests passed. The [current validation](validation.json) records 1,406 passes,
80 explicit skips and 11 failures in the first clean-clone suite. All failures
came from metadata tests depending on available host disk space. Their fixture
now controls capacity, and a new below-floor test preserves the unchanged
runtime refusal: all 13 module tests pass. Public lint, formatting and document
checks pass. [Installed checks](installed-example.json) also cover acceptance,
rejection, abstention and review with owner files absent and execution blocked.
The [platform CI](https://github.com/manfromnowhere143/nisayon/actions/workflows/ci.yml)
is a separate full-suite result. No new simulator, policy training or physical
trial is claimed.
