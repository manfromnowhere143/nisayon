@stealthg0dd I checked the published `arisole-eval==0.1.2` wheel behind this example. There is a missing-label case worth resolving before using its default exit code as a CI gate.

With 30 shared seeds but only one fully labeled pair, `evaluate` retains 29 `INCOMPARABLE` pairs. `gate` still uses `summary.paired_episodes == 30` for the evidence threshold and regression denominator. The result is `REVIEW`, exit **0**, despite the default minimum of 20 comparable episodes. This is not an overall `PASS`; the missing trajectory metric produces `REVIEW`, which does not fail CI by default.

The reproduction below uses constructed metadata, with no robot or policy execution. Run it in an environment containing the published 0.1.2 package:

```python
import json
import os
from pathlib import Path
import subprocess
import sys
from tempfile import TemporaryDirectory

env = {**os.environ, "ARISOLE_TELEMETRY": "0"}
with TemporaryDirectory() as temporary:
    root = Path(temporary)
    for arm in ("baseline", "candidate"):
        run = root / arm
        run.mkdir()
        (run / "eval_info.json").write_text(json.dumps({
            "per_episode": [
                {"episode_ix": i, "seed": 100 + i,
                 "success": True if i == 0 else None}
                for i in range(30)
            ],
            "aggregated": {"n_episodes": 30},
        }))
        (run / "run_meta.json").write_text(json.dumps({
            "task": "constructed-label-coverage-control",
            "environment": "software-fixture", "embodiment": "none",
        }))
    prefix = [sys.executable, "-m", "arisole_eval"]
    subprocess.run(prefix + ["evaluate", "--baseline", str(root / "baseline"),
        "--candidate", str(root / "candidate"), "--out", str(root / "comparison.json")],
        check=True, env=env, capture_output=True)
    process = subprocess.run(prefix + ["gate", str(root / "comparison.json"),
        "--out-json", str(root / "gate.json"), "--out-md", str(root / "gate.md")],
        env=env, capture_output=True)
    comparison = json.loads((root / "comparison.json").read_text())
    gate = json.loads((root / "gate.json").read_text())["gate"]
    print(comparison["summary"])
    print(gate["outcome"], process.returncode)
```

Counting only fully labeled transitions for the gate, while retaining every row in the comparison, changes this to `INSUFFICIENT_DATA`, exit **2**. Missing labels also need an explicit insufficient-data reason when enough other labels exist: 6 regressions among 30 observed pairs and 30 unknown pairs should report **6/30**, not **6/60**. That fraction describes observed pairs; missingness still prevents affirmative acceptance.

I froze 12 CLI controls before execution. The release passes four; the small correction below passes all 12. Complete-data controls retain their outcomes, and comparison rows and metrics remain unchanged. Both variants pass 20 original sdist tests. The other three fail because the archive lacks `.arisole/reliability.yml` and `.arisole/reliability.ci-smoke.yml`; I have not counted those as qualified.

This finding concerns the external package, not LeRobot's evaluator. The proposed correction follows; it is bounded to the default paired-label gate and does not validate seed identity or establish policy reliability.
