# What the unused audit tells us

Neither retained comparison shows an advantage for the additional checks.
The [scripted trace audit](PARITY_ANALYSIS.md) finds a common fixed selector
that chose a known remedy before probing. The [bounded model comparison](BOUNDED_AGENT_COMPARISON.md)
instead retained six live CLI invocations, public packets, structured requests,
events and token receipts: `gpt-6-astra`, medium reasoning, CLI 0.154.0. These
receipts establish observed calls and settings, not provider-side weight identity.
Both arms requested the same execute-and-freeze action in one call per assignment.

## Availability and relevance

B's response schema exposed `audit`; A's did not. Its description accurately
offered integrity, measurement, timing, progress, scope and provenance checks
over already executed runs, without physics or future confirmation outcomes.
The controller could return those fields in the next public packet. The budget
allowed four calls, eight diagnostic rollouts, 600 diagnostic seconds and
200,000 input-plus-output tokens per assignment; each scored trial used one
call and three rollouts. No optional audit request or failed audit invocation
occurred in the comparison.

A separate [interface positive control](results/retained-audit-probe-001/probe.json)
ran the actual snapshot/evaluator path on a linked copy of E01-r01/B's retained
three-run diagnostic store. Integrity verified, all three run summaries returned,
and acceptance stayed unresolved without fresh confirmation. Audit time was
2.299253 s; the recorded command took 2.463573 s. It executed no physics and no
model call; source bytes were unchanged. This demonstrates a callable path and
observable result at modest cost, not a model's response to that result or an
efficiency benefit. It is post-comparison development evidence.

Both arms already received working and changed configurations and ordinary
checks showing a gripper-sign mismatch and observation backlog. Both could
inspect the same full traces; their observed shell commands only read the
initial packet. The packets excluded the authored incident name, known-remedy
list and confirmation seeds/outcomes. Equal diagnostic information made this
known repair direct. No remaining diagnostic question that the optional audit
could settle is visible in the requests. Fresh outcomes remained unknown, and
the tool could not supply them. The record supports redundant information on
this incident; it does not reveal why the model declined the tool or exclude
all possible interface defects. Separate hidden-fault authorship was not established.

B still used Nisayon's execution receipts, closed-loop reruns, ordinary checks,
finite candidate authority, budgets, sealing, mandatory diagnostic evaluation,
joint candidate freeze, condition reservations and mandatory fresh confirmation.
Zero optional audit requests does not mean zero Nisayon functionality.

60100–60131 and 60200–60231. They are disjoint. D05's prefix identities and

The wall estimate is `T_A / C`, using A's measured confirmation as the common
fixed-cost estimate. Using B's measured confirmation gives 1.120× and 1.220×.
Measured wall varies; these are not universal lower bounds. Run ceilings are
exact only while keeping these selected candidates, confirmation schedules and
acceptance obligations. They generously charge zero diagnostic runs, although
the current bounded controller also requires three per assignment. Prefix
executions are included once. Even free diagnosis cannot reach 2× here.

The bounded comparison's disjoint [cost partition](BOUNDED_AGENT_COMPARISON.md)
separates simulation, model planning, checking and preparation. Its confirmation
total is about **343–346 s per arm**, of which only 230–234 s is simulation;
using simulator time alone understates mandatory work. Shared setup, qualification,
failed attempts and post-run checks are separate from trial cost. Human effort,
engineering-session tokens, provider charges and energy remain unknown. No
amortization or zero substitution supplies a favorable result.

## Next decision

Stop repeating D07 and expanding features on this evidence. A discriminating
comparison would need a separately authored ambiguous engineering decision where
a specific additional observation can change the candidate before an expensive
wrong confirmation, ordinary telemetry cannot resolve it equally cheaply, and
the measured avoidable cost can fund the proposed benefit. No such new case or
credible cost opportunity is supplied here. Do not execute another screen until
that premise and a matched rule are frozen. The product advantage remains unproved.
