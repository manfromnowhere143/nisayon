Evidence / Portable review

A decision you
can inspect.

Carry the complete retained experiment in one file. Review its integrity and assessment without recreating the original robotics environment.

01

Export the retained store

The Nisayon SDK writes a versioned .nisayon.zip package containing the plan, saved assessment and retained evidence, including failed attempts. The export records file hashes and byte lengths.

nisayon-qualify export ./run-001 \
  --out ./review-001.nisayon.zip

Export outside the source store. Packages contain original logs and paths; export does not redact them. Review the contents before sharing.

02

Reassess with Python

The installed SDK checks archive structure and file identities, then recomputes the software assessment from retained records. It does not import or execute the owner project.

nisayon-qualify review \
  ./review-001.nisayon.zip

Integrity, software acceptance and deployment acceptance remain separate. Matching archive bytes do not authenticate their author or establish physical truth.

03

Inspect in the browser

Open the review instrument and choose the file. Verification runs locally; the file stays in browser memory and is not uploaded.

Inspect the saved decision, probes, first reported differences, scope, costs and original records. Numbers retain their original representation. An invalid replacement leaves the previously opened package available.

The browser checks transport integrity and reads the saved assessment. Use Python review to recompute it.

What remains unresolved

An adoption decision on declared software probes does not authorize a physical deployment. Correct continuation, unseen failures, transfer and complete engineering cost need their own checks.

Portable records make an assessment easier to inspect; whether Nisayon leads to better decisions with less complete review effort is still to be measured. The installed guide is docs/PORTABLE_REVIEW.md.
